# Audit — EC-C004 rules kernel K2: agreement with the frozen models (S008)

**Subject:** `formal/EndgameChess/Rules/{Lemmas,AgreeKK,AgreeKBK}.lean`.
**Auditor:** same session (S008); no independent second reader.
**Claim:** on their material classes, the bespoke move relations of the frozen theorems agree exactly with the general kernel's `Legal`:
- EC-T0001's `KK.LegalKK`;
- EC-T0002's `KBK.Step`.

Consequently, "dead" in each frozen model is "dead" in the kernel. This closes trust gap **G1** (move-set fidelity), *modulo* the kernel bridge `docs/RULES_KERNEL.md`, which still awaits independent human review.

## 2. Hostile checks
1. **Exactness, not inclusion.** Each agreement theorem is an `↔` together with the embedding equality `q = emb b`, so the kernel has no extra moves and the model has no missing ones. Every kernel move kind was ruled in or out:
   - castling is excluded because there are no rooks (`canCastle_false_of_noRook`);
   - pawn moves and promotions are excluded because there are no pawns;
   - captures by the strong side are excluded because they would capture the king (`targetOK`);
   - a strong move onto its own bishop is excluded by 3.1;
   - the weak king's capture of the bishop is included.
2. **Hypotheses are not vacuous.**
   - `kernel_kk_has_move` shows an admissible K vs K position (Ka1 vs Kc3) whose kernel embedding has a legal move.
   - `kernel_kbk_check_has_move` shows that EC-T0002's check position satisfies `LKBK`, that its embedding is in check in the kernel, and that it has a kernel-legal move.
3. **Are the hypotheses necessary, and the right ones?**
   - `legal_ofKK_iff` needs only distinct kings. The frozen `KKState` can represent `wk = bk`, which is junk; it is excluded.
   - `legal_ofKBK_iff` uses `LKBK`, which is the frozen theorem's own hypothesis.
   - The deadness transfer uses the invariant classes `Admissible` and `Closed`, which are closed under steps (EC-T0001 L3; EC-T0002 `closed_of_step`).
4. **Mate correspondence.**
   - On `Admissible` / `LKBK`-side `kk` positions, both kernel mate and model mate are false: there is no check.
   - On `kbk` positions, kernel mate ⇔ `KBK.Mated`: the check correspondence comes from `inCheck_side`, and "no move" corresponds through `legal_ofKBK_iff`.
5. **Colour orientation.** `ofKBK` uses `strongColour`. The capture branch's embedding `ofKK (KBK.toKK …)` was checked square by square for both colours (`play_capture`, by cases on `σ`).
6. **Embedding flags.**
   - The embeddings set no castling rights and no en-passant target. These are the only meaningful values: there are no rooks or pawns.
   - A kernel position with the same pieces but nonsense flags (rights without rooks) is *not* covered by these theorems. Such a position is not reachable from the initial position; S009 is to prove the reachable invariants.
7. **Frozen modules and K1 untouched.** The hashes of `KK.lean`, `KBK.lean`, `Board`, `Position`, `Moves` and `Sanity` are unchanged; see the closeout.
8. **Trusted base.** Every new declaration's axioms are a subset of `[propext, Classical.choice, Quot.sound]`. There is no `native_decide`. `decide` is used only for small closed facts in the non-vacuity theorems.

## 3. What G1's closure now means
The bespoke-relation trust items in the EC-T0001/EC-T0002 manifests (A1 aside) reduce to **one** reviewable artefact: the kernel encoding, through its clause table `docs/RULES_KERNEL.md`. That table has supporting evidence:
- kernel-checked sanity theorems;
- perft agreement between two independent implementations and the published values.

It is still not machine-verifiable against the FIDE text, and it needs an independent human review.

**Remaining gaps:**
- **G2** (positions reached by capture from larger material; kernel reachability from `initial`);
- **G3** (the Article 5.2.2 rule step, to be made an explicit named rule).

Both are S009.

**Verdict:** K2 is complete. No defect found.
